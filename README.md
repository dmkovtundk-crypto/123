# FlexGlobalLogistics — корпоративный портал (первичный проектный документ)

## 1) Цель проекта
Создать закрытый корпоративный сайт (интранет-портал) для компании **FlexGlobalLogistics** с:
- ролевым доступом для сотрудников (примерно 20 пользователей);
- публикацией внутренних объявлений;
- хранением и структурированием общих материалов по темам;
- централизованной авторизацией по логину/паролю;
- журналированием входов (кто/когда/с какого IP);
- быстрыми переходами на внешние корпоративные сервисы (Астралдоки, Эльба, Контур Диадок и т.д.).

---

## 2) Пользователи и роли

### 2.1. Базовые организационные группы
- Руководство
- Финансы
- Бухгалтерия
- Менеджеры
- Администратор портала

### 2.2. Системные роли (RBAC)
1. **Администратор**
   - создает/блокирует учетные записи;
   - выдает/сбрасывает пароли;
   - назначает роли и права;
   - просматривает журналы входов и активности;
   - управляет разделами/ресурсами.

2. **Редактор объявлений** (может быть выделенная роль или право внутри отдела)
   - публикует объявления;
   - редактирует/архивирует свои публикации.

3. **Сотрудник**
   - авторизуется в системе;
   - читает объявления;
   - работает с доступными ему общими ресурсами;
   - использует каталог внешних корпоративных сервисов.

---

## 3) Функциональные требования (MVP)

### 3.1. Авторизация и управление доступом
- Вход по логину и паролю.
- Принудительная смена пароля при первом входе (рекомендуется).
- Минимальные требования к паролю (длина/сложность).
- Блокировка после N неудачных попыток входа (рекомендуется).
- Разграничение доступа по ролям и разделам.

### 3.2. Журнал входов и аудит
- Фиксация:
  - пользователя;
  - даты/времени входа;
  - IP-адреса;
  - результата попытки (успешно/ошибка).
- Экран администратора со статистикой:
  - последние входы;
  - фильтры по сотруднику/дате;
  - аномалии (например, частые неуспешные входы).
- Экспорт журнала (CSV/XLSX) — желательно.

### 3.3. Объявления
- Лента объявлений на главной странице.
- Категории (например: IT, HR, Финансы, Общие).
- Публикация с заголовком, текстом, датой, автором.
- Опционально: закрепление важных объявлений вверху.

### 3.4. Общие ресурсы (внутренние «диски»)
- Структура папок по темам/отделам.
- Загрузка и скачивание файлов в рамках прав доступа.
- Базовые метаданные (автор, дата загрузки, размер).
- Ограничение типов/размеров файлов.
- Поиск по названию файла/папки.

### 3.5. Каталог внешних сервисов компании
- Раздел «Полезные сервисы» с карточками/ссылками:
  - Астралдоки;
  - Эльба;
  - Контур Диадок;
  - и другие корпоративные сайты.
- Отображение краткого описания каждого сервиса.
- Возможность управления списком ссылок администратором.

---

## 4) Нефункциональные требования
- Интерфейс на русском языке.
- Адаптивность для ноутбука/планшета (минимум desktop-first).
- Базовая отказоустойчивость и резервное копирование файлов/БД.
- Логирование ключевых действий пользователей.
- Время загрузки основных страниц в корпоративной сети — целевое до 2 секунд.

---

## 5) Требования безопасности
- Хранение паролей только в виде стойких хешей (Argon2/bcrypt).
- Принудительный HTTPS.
- Защита от типовых веб-угроз:
  - CSRF;
  - XSS;
  - SQL-инъекции.
- Разграничение прав на уровне backend (не только UI).
- Ограничение доступа к административным страницам.
- Регламент хранения логов доступа (например, 6–12 месяцев).

---

## 6) Предлагаемая структура разделов сайта
1. **Главная**
   - приветствие;
   - важные объявления;
   - быстрые ссылки на ключевые разделы.

2. **Объявления**
   - фильтрация по категории;
   - архив объявлений.

3. **Общие ресурсы**
   - папки по отделам/темам;
   - управление файлами по правам.

4. **Сервисы компании**
   - список внешних систем и инструкций по входу.

5. **Администрирование** (только для админа)
   - пользователи и роли;
   - журнал входов;
   - настройка разделов и ссылок.

---

## 7) Первичный план реализации

### Этап 1 — Проектирование (1–2 недели)
- Уточнение ролей и прав по отделам.
- Согласование карты страниц.
- Подготовка прототипа интерфейса.

### Этап 2 — MVP разработка (2–4 недели)
- Авторизация + роли.
- Объявления.
- Общие ресурсы (базовый файловый модуль).
- Журнал входов и админ-панель (базовая).
- Каталог внешних сервисов.

### Этап 3 — Тестирование и запуск (1–2 недели)
- Функциональное тестирование.
- Проверка прав доступа.
- Тестирование безопасности (базовый чеклист).
- Обучение администратора и публикация регламентов.

---

## 8) Вопросы для уточнения перед началом разработки
1. Нужна ли интеграция с Active Directory / LDAP?
2. Планируется ли 2FA (код в приложении/SMS)?
3. Какие лимиты на объем общего файлового хранилища?
4. Нужны ли версии документов и история изменений файлов?
5. Какие данные должны видеть руководители в отчетах активности?
6. Нужны ли уведомления на email/в мессенджер о новых объявлениях?
7. Требуется ли мобильная версия или достаточно адаптивного web-интерфейса?

---

## 9) Рекомендуемый следующий шаг
Провести 60–90 минутную сессию с представителями: руководство + бухгалтерия + финансы + IT/администратор, чтобы утвердить:
- финальный перечень ролей;
- матрицу прав доступа;
- структуру папок общих ресурсов;
- список обязательных внешних сервисов;
- приоритеты первой версии (MVP).
